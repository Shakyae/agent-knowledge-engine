# 最小可验证实验计划（未执行）

## 前提和边界

须另获实施及模型调用授权；在隔离、可丢弃的 Git 测试仓库和非生产配置进行，不触及真实知识库。记录 DSH/插件版本、实际启用组件、权限、模型和 Preset；不预设成员必然具有某个工具。先建立包含已核实的四类经验、负例、过期项、同义词、跨目录案例的带标签测试集，并预留不向执行者提示知识路径的盲测任务。记录任务成功的独立判据及证据；不要把保存成功当作复用成功。

## 运行矩阵

1. **Single Session**：在任务 A 中遇到真实可复现问题，提出候选；人类批准后以 Git 提交形成正式知识。启动全新任务 B，任务描述不包含知识路径，验证主动定位原文、适用性核验、行动中正确应用及结果。再运行无价值经验的任务，验证跳过；不同意发布时不得改正式知识。
2. **双人 Team（Lead + 1 成员）**：成员在子任务前独立检索并复用；分别测试候选由成员及 Lead 提出，只有未参与生成且具备能力、可用的另一方才可审核。角色冲突、成员不可用或无法验证独立性时转人工；指定唯一发布者。以实际 roster 和权限为准，记录过程证据。
3. **多成员 Team（至少三个实际参与者）**：不同执行者分别检索不同领域知识并各自产生候选，独立成员审核，单一发布者串行处理同一批次；测试两候选修改同一文件、源版本变化及审核后内容变化，必须重新审查或拒绝发布，不能丢失更新。不可用或中断则停在待审，不通过超时自动发布。
4. **对照与退化**：同任务对照无知识流程、纯提示流程、提示加可选脚本；对缺少搜索工具、指令被预算截断、无法访问 Git、旧知识不适用、恶意知识文本、无匹配、搜索截断等情况验证明确降级；防止模型把检索不到当成知识不存在。

## 可观测性与判定

- 预先定义每题的相关文档、必要验证动作、期望修改与测试结果；评审者用盲标独立判定，记录检索调用、所读原文、适用性判断、实际代码/行为引用及最终测试证据。
- 主动检索率 = 需要知识的任务中，在首次关键实施前执行有效检索的比例；召回率 = 找到的应找知识数 / 标注相关数；正确应用率 = 成功应用且验证的任务数 / 适用任务数。分别统计错误应用、过期知识误用、无匹配误报和不必要检索。对每个样本给原始分子分母，不用小样本宣称统计显著。
- 对比端到端耗时、检索工具调用次数、输入/输出 token、模型费用、候选数和无意义候选比例；对简单任务测额外调用及耗时，并记录服务/模型波动。预算与验收阈值须事先由项目负责人决定，未测前不得声称低成本。
- 安全门：记录有限样本中未经人工批准的 Single 正式发布次数，目标为零；自动发布必须满足独立性、证据、范围、内容绑定与并发保护，否则预期不发布；测试人为插入错误、伪造审核、越权和脏工作区。有限样本中零次违规不能证明强制安全，尤其共享 workspace-write 的纯提示组可绕过；真实权限对抗测试须先获额外授权，并记录审核主体、内容版本和写入路径。Git 回滚使用专用测试仓库，并验证恢复和追溯，不覆盖用户未提交变更。
- 观察记录可用人工审阅的任务日志、git diff、审批记录与测试结果；工具动作检查最多证明调用/文件状态，不能单凭调用证明阅读理解、正确使用或审核独立。

## 执行顺序与决策门

先跑 Single 的写入→跨新任务盲测复用；再跑双人及多成员并发/故障；最后才比较可选脚本。各组使用等价任务与固定基线，避免先验知识泄漏；记录失败及重试，不为通过率剔除失败。若召回或正确应用不足，先改检索规则/索引；若成本超标，降低触发范围；若审查独立性、权限或并发控制不可靠，维持人工审批。自动发布只能在政策及可执行边界均由用户批准且实验支持后另行设计实施。
