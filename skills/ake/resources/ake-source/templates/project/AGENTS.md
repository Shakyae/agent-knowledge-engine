# AKE Knowledge Operations

- For implementation, architecture, debugging, testing, deployment, or risk changes, retrieve applicable knowledge from `.agents/notes/`, `docs/defensive-patterns/`, `docs/postmortem/`, and `docs/cookbook/` before work.
- Knowledge is organized by kind and lifecycle; when a task makes relevant knowledge useful, use the visible `ake` Skill and retrieve it on demand before work.
- Make retrieval and capture visible before the first related AKE CLI action; coalesce consecutive same-stage calls into one notice. In Agent Teams, the Lead/owner sends one unified user notice; members report to the Lead and do not repeat it. Identify the relevant Note, Defensive Pattern, Postmortem, or Cookbook category and summarize applicable hits. Triggers are stage-specific: task-before triggers retrieve/applicability only; task-after triggers assess value/evidence; explicit `/ake` follows the requested stage(s). Continue applicable, permitted steps without redundant “continue?” pauses; candidate creation/review happens only for supported, reusable knowledge with sufficient relevant evidence. Automatic completion-phrase routing applies only after substantive engineering work when the `ake` Skill is loaded and the user explicitly confirms verification/completion; ordinary Q&A does not automatically trigger it. This is prompt-level routing, not a host guarantee. Prefer an eligible independent reviewer and wait for its actual result; do not treat dispatch or silence as review. If an independent reviewer is unavailable, pause and report that limitation rather than claiming self-review is independent. Keep reviewer labels PASS / PASS WITH LIMITATIONS / BLOCK separate from the CLI's approve / request-changes / reject verdicts; preserve CLI interfaces. Do not block solely for missing session IDs, event numbers, standalone evidence files, or unrelated topics. Allow at most one automatic revision followed by another independent review. After review, wait for explicit user authorization before `approve` or `publish`; automatic authorization is not the default. Report `AKE · 本次无新增知识` only when there truly is no reusable result; if a potentially useful result lacks core evidence, report it as pending evidence with the gap and verification path. Disclose any unpublished candidate and why it remains pending.
- These instructions are soft constraints, not security isolation: ordinary file tools can bypass them and declared identities cannot be independently verified by AKE.
